# Steward

Companion owns classification, collection references, sale rules and market coordination. AutoRetainer owns existing disposal and storage workflows. Preserve other plugins' configurations; import read-only. Default dry-run. Exact item IDs, dyes ignored, both native plates and Glamaholic, level-one glamour gear, nonmarketable blues and special/unknown acquisition sources preserved until collected. Marketable blues are not protected by the blue-rarity rule; other protection rules still apply. Marketability means item eligibility for marketboard trading, not whether listings or fresh prices exist. Confirm exact collected copies before surplus disposal. Unknown is never zero or absent. User exclusions override all handling. Keep native acceptance distinct from automated validation.

Execution requires live readiness, protocol 6, fresh protection imports and current source fingerprints. Stale populated collection sets never authorize disposal. Managed discard is denied. Do not delegate managed bulk operations without a per-item submission gate. Persist uncertain-run holds immediately, including planning failures, and leave automatic off after clearing one. Only release a proven owned handoff/control lease; expiry recovery must not unlock another plugin's work or modify general suppression. Read back native market values, correlate complete current requests and bind confirmations to their parent/host. Keep the last-copy omission active across live refreshes. A safety-protocol upgrade starts in dry-run mode. Explicit AutoRetainer protection also gates companion-owned actions; unavailable protection is a hold. Failed saves must not enable automatic execution or relax in-memory review guards.

Ordinary normal-dungeon and normal-mode raid sources do not trigger the blue rule. Alliance, Savage, Coil and other high-end sources do; conservative alternate-source merges win. Full dresser uses the configured empty-slot reserve, then retainer overflow with saved character-scoped pending-collection holds. No inventory/retainer copy satisfies collection ownership. Clear holds only after live exact dresser/armoire ownership (armoire eligibility prefers armoire). Cleanup is opt-in and preserves required last copies; armoire migration persists a hold before restoration. Store requires protocol 6, owned handoff, source/destination acknowledgement and player alerts.

LogOnly defaults on and gates every native action independently of Automatic. Changing review mode stops work and never enables execution. Review logs use the same copy-removal simulation as execution; cached observations stay labelled. Safety-revision-6+ states require an explicit valid PendingCollection field, and a missing authoritative file must not silently migrate a post-overflow compatibility mirror.

New listings use ListingPlanner for both execution and log-only pricing/stack thresholds. Fill market slots with a dynamic pass after each acknowledged listing; never prequeue guessed remainder quantities or consume capacity for skipped candidates. Additional stacks match a lowest own price rather than undercutting it. Bind actions to the captured world/retainer/source and read actual occupancy before commit. Cached preview estimates remain labelled and do not authorize native submission.
