# Steward

A collection-aware companion for the maintained AutoRetainer integration fork. Open `/steward`. Defaults to log-only review and dry run and holds AutoRetainer item actions for connected characters until automatic execution is enabled. Other AutoRetainer functions remain its responsibility.

## Agreed rules

- Both Glamaholic (nested and legacy configurations) and native glamour plates are references.
- Preserve one exact collection copy of referenced/curated items, level-one equipment, nonmarketable blues (except confirmed ordinary dungeon/normal-raid sources) and special-source equipment. Marketable blues receive no protection from the blue-rarity rule, although all other protection rules still apply. Marketability means whether the item can be traded on the marketboard, independently of available listings or cached prices. Dyes do not affect protection or duplicates. Equipped and gear-set equipment stays protected.
- Armoire-eligible items are directed to the armoire, including pieces restored from the dresser. For other items, an exact item in the dresser or armoire satisfies collection ownership; surplus copies may be disposed of under AutoRetainer's existing settings. Ordinary unreferenced dungeon/crafted equipment can be unwanted even if uncollected. Unknown acquisition sources stay held. Crafted items are recognized from the game Recipe sheet. Dungeon sources are indexed incrementally through Glamour Log’s existing GetItemsFromContent IPC; missing sources stay conservative and can be overridden in Rules.
- Exclusions override all handling, including market actions. Both Metallic Silver Dye (8743) and General-purpose Metallic Silver Dye (13116) are excluded once on initial setup, with IDs verified against installed English game data. You can remove either exclusion later; it will not be re-added. No reserve or speculative market-strategy system is added.
- Ordered sale rules reserve worthwhile surplus before disposal, with minimum unit/stack values and stack size. HQ/NQ comparison is configurable. Known own retainer listings, including Allagan Market listings on the current world, are excluded from competition. If an own listing is already cheapest, do not lower it.
- Missing, future or stale competitor prices hold marketable items rather than valuing them at zero.

## Setup and controls

Build both plugins with `./tools/build.ps1`. Install the fork as a replacement for upstream AutoRetainer, never alongside it; its identity and existing configuration are preserved. Install Steward separately. Repository releases are development previews with immutable archives and checksums. Native testing is still required.

Update both plugins together: Steward requires AutoRetainer inventory-policy protocol 6 and holds on an older bridge. This safety upgrade resets automatic execution to off on first load, including previously enabled installations. Open the dresser, native plate editor and armoire to establish collection/reference evidence. Cached observations never substitute for unavailable live data. Zoning or native data unloading can therefore pause actions until the required data is loaded again. Only complete native reads replace collections, including unlocked outfit pieces. Source inventory slots and glamour references are refreshed before permission/submission. Glamaholic, Market Buddy and Allagan Market files are imported read-only; failures are visible. Expected Market Buddy settings becoming unavailable hold market execution instead of silently using defaults. Universalis current-world listings are fetched in bounded background batches, including in log-only mode. The source can be disabled in Rules. Server upload times govern freshness; known own retainers and unidentified sellers are excluded from competitor valuation.

Preview explains every inventory/armoury decision. Rules allows exclusions, keep overrides, acquisition-source overrides, curated-list imports and ordered sale rules. The JSON editor exposes category and quality filters as well. A rule uses its minimum values against the actual planned stack, and the final undercut price is checked again. Global Automatic starts disabled. Stop cancels queued work and leaves managed actions held. An already submitted native action may complete.

Preview and all companion-owned actions also query AutoRetainer's explicit protection through its existing read-only API. Protected items remain kept; unavailable protection holds. Enabling automatic execution requires a connected, reviewed character and a successful settings save. A failed save leaves execution off. Review recovery only clears local transaction state after the backend guards are saved successfully; saving failures restore in-memory holds.

Automatic execution starts off on **every plugin load**, including normal restarts. Re-enable it after checking the preview. This prevents an unsuccessful Stop save from restoring an old enabled flag on restart. All companion queue operations persist a pending record before their first native step and clear it only after acknowledgement and cleanup. Interrupted work requires review on the character that owned it. AutoRetainer's vendor, desynthesis and armoire paths likewise submit once and wait for the expected source change before proceeding. Stop AutoRetainer's queued work and close pending dialogs before clearing a stopped run or detaching.

Steward migrates its existing configuration to `Steward/steward-state.json` inside Dalamud's plugin configuration directory; this synchronous private state becomes authoritative. The ordinary Dalamud configuration remains a compatibility mirror. The fork separately migrates its companion ownership/hold markers to `AutoRetainer/steward-policy.json`. Its usual configuration, identity and unrelated settings retain their existing handling. Ordinary AutoRetainer configuration imports cannot remove that private policy. Back up these private files with the plugin configurations; do not delete them to clear a stopped run. Damaged safety state holds startup instead of silently resetting protections.

AutoRetainer's retainer postprocess handoff opens inventory, withdraws eligible items through the fork, waits for source and destination evidence, then opens the market list and runs sequential listings/repricing. Current-retainer work can also be requested explicitly. Market Buddy's named lock is released on completion, failure, cancellation or unload. AutoRetainer postprocessing is released only for our own handoff; its bridge watches the lease and releases a stranded Steward handoff when the connection expires. Standalone market/dresser work use a separate owned control lease that pauses AutoRetainer's main loop while idle control is held and expires if Steward disappears. The general suppression flag is never overwritten. Losing ownership stops Steward. Retainer identity and source fingerprints are checked throughout. Unknown outcomes and partial planning failures immediately disable automatic execution and persist an inventory-review hold. Clearing the hold leaves automatic execution off. Menu timeouts and partial delegated-request failures also hold.

Armoire/Dresser/GC/Desynth/Vendor buttons request AutoRetainer's existing workflows. The companion dresser request leaves the dresser open for the native targeted adapter. While an open dresser is idle, automatic mode processes permitted deposits and cleanup through the same queue. AutoRetainer feature settings and explicit protections still apply. These requests do not rewrite existing disposal lists. Every armoire-eligible item gets a collection route before sale/disposal. Clean open dresser restores eligible loose items only after evaluating protection with that exact dresser copy omitted, even when live data is refreshed during the check. Partial-outfit restoration selects only the permitted unlocked piece and checks the destination inventory. Targeted loose-item deposits require the matching native source and item-specific confirmation. Bulk Glamour Log outfit conversion is held for managed characters because its IPC cannot revalidate each item at submission; unsupported conversion dialogs also stop the queue. Managed discard, including delayed discard confirmations, is disabled. GC delivery requires an owned, unexpired pending item with unchanged inventory, matching reward text and fresh protection permission at confirmation. Native acceptance remains required.

History distinguishes policy permission from actual execution. AutoRetainer owns its disposal results; Steward records confirmed transfers/listings/restorations and request failures. The session view is bounded; `history.jsonl` remains local to Steward's configuration directory. On unload the character's claim remains, so unavailable policy cannot accidentally resume disposal. Integration > Detach explicitly restores original AutoRetainer rules.

GC commit buttons are one-shot while awaiting acknowledgement. Backend uncertainty persists a review hold in AutoRetainer as well as Steward; clearing it requires resolving pending confirmations and using the existing review-clear button. Owned standalone control/review holds reuse AutoRetainer's existing YesAlready/TextAdvance pause requests. Cancelling an owned pending dresser confirmation selects No. Independent third-party UI automation and native pause/confirmation behaviour still require in-game acceptance.

## Log-only verification before execution

**Rules → Log only — do not change any items** defaults on, including when upgrading settings that lack this field. It records proposed listings/prices, disposal and, when the cleanup toggle is enabled, dresser restoration/armoire migration without submitting any managed item action. All managed disposal, listing, retrieval and storage permissions remain denied even if an automatic flag is present. Switching modes stops queued work and leaves automatic execution off; already submitted game actions require the existing cancellation/review handling.

Use **Write review snapshot now** for a complete new snapshot, or leave the mode enabled for scans every five seconds. Changes are written to `review.jsonl` beside the private Steward settings, with readable entries also in History. Unchanged observations are suppressed. Entries identify the character, item ID, quantity, source/container/slot, proposed action and reason. Cached retainer observations are explicitly labelled and restricted to identified current-character retainers; no retainer menus are opened for logging. Pending collection holds and readiness gaps are logged so zero proposals cannot be mistaken for complete verified coverage. No log write failure permits execution.

Only turn log-only off after reviewing the output, then separately enable automatic execution. The dresser-cleanup toggle remains independently opt-in. This mode does not disable player-controlled game actions, unrelated plugins or AutoRetainer's non-policy functions such as venture collection.

## Automatic listing and market preview

Normal AutoRetainer retainer postprocessing opens the current retainer inventory/market and runs the companion market queue. New listings require an enabled matching sale rule, readable Market Buddy preferences when imported, and fresh valid competition. AutoRetainer retains coordination and its existing inventory/disposal workflows. Universalis supplies cached estimates; native market comparisons still gate submissions.

The queue reprices existing eligible listings first. It then reads actual market occupancy and selects a live eligible source stack. Each listing uses the sale-rule/Market Buddy stack caps and actual unit/total thresholds. After confirmed source removal and a matching new market slot, it re-reads the remainder and available slots, repeatedly splitting the same source stack until exhausted or the market is full. A below-floor remainder, missing comparison or rejected source does not reserve a slot; other candidates are tried. Skipped sources are reconsidered on a later pass. Additional stacks match a known lowest own listing instead of repeatedly undercutting it. Bound/collectable/glamoured instances are not submitted as new listings.

**Market preview** displays the current retainer's actual slot holes, split quantities, unit and total prices, repricing proposals and hold reasons. Open the retainer selling list manually while Log only remains on; the preview itself opens no game menus or in-game market searches. Background Universalis requests, existing caches or complete comparisons observed from the game provide price references. Cache-based own-price coverage outside the current retainer may be incomplete and is labelled. Missing/stale prices or unknown capacity produce holds/status messages, never guessed values. Live execution requests a complete current game comparison and validates prices, quantities, protections, world, retainer and occupancy again before submitting. See [market listing details](docs/market-listing.md).

## Dresser capacity, overflow and cleanup

See [storage policy and acceptance checks](docs/storage-policy.md). The empty-slot slider defaults to 20. Protected overflow is deposited with available retainers using AutoRetainer, with persistent per-character protection until collection is confirmed. Chat, notification and history alerts report overflow, destinations and unresolved space shortages. Automatic retainer visits need an accessible summoning bell; otherwise the items stay protected and the player is alerted.

Dresser cleanup is opt-in and starts disabled. Its preview checks all rules. Normal dungeon/normal-mode raid blues can be restored if nothing else protects them; Alliance, Savage, Coil and other high-end sources remain protected. Eligible dresser pieces are restored under a durable armoire-transfer hold and passed to AutoRetainer's existing armoire workflow. Retainer overflow does not count as a collected copy and is not withdrawn while the dresser remains at its reserve.

## Curated Eorzea Collection list

The bundled list uses a job-balanced Eorzea Collection survey, an official usage-census cross-check and exact per-item all-time use counts. Frequency leads; likes from the most-loved results page support the ranking. Exact game IDs are verified against installed English game data. Level-one equipment, nonmarketable blues outside the ordinary-duty exception and identified special rewards are covered by other rules. See [the full list, method and slot/job coverage](docs/common-glamour.md) and [saved evidence](docs/data/common-glamour-evidence.json). The survey is bounded and cannot infer every personal preference. The bundle can be disabled in Integration. Additions can be imported from a reviewed JSON file with an `items` array. Every entry needs a numeric `itemId` and a `source` URL on `ffxiv.eorzeacollection.com`. See `docs/common-glamour.example.json` and `Steward/data/common-glamour.json`.

## Current verification limits

Local builds and automated rules/import/pricing/cancellation checks pass. No FFXIV in-game tests have been performed. Market prices require complete responses matching the native item/request, followed by readback of both the native agent and visible price/quantity fields and a final threshold/source check. Network callbacks only enqueue managed snapshots; native reads run on the framework thread. Confirmation parent/host links must match the expected source window. Unknown identities/layouts hold. Callback behaviour, ownership fields, request IDs/counts, retainer menus, withdrawals and acknowledgements still require native acceptance. Cross-zone workflows may remain held when native collection data is cleared; a safe refresh path for every location has not been verified.

Glamour Log’s bulk outfit IPC has no per-item submission callback, so it is blocked for managed characters. Acquisition indexing depends on source metadata; unknown equipment sources stay held. Common-glamour discovery is sampled and cannot infer every personal keep preference. Allagan Tools inventories are cached previews, never execution authority. Automatic travel/storage/disposal schedules and configured disposal lists remain owned by AutoRetainer. The safeguards cover connected, managed characters; an upstream installation or a deliberately detached character retains its original AutoRetainer behaviour. See [the safety review](docs/safety-review.md) for fixes, automated evidence and the native acceptance boundary.
